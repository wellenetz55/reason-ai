# UI・デザイン方針

要望（2026-10-07）: Appleのようにシンプルだが、デザイン性に富んだもの。

## 原則

1. **一画面一仕事**。発散は発散だけ、承認は承認だけ。タブやモーダルを重ねない
2. **余白で構造を見せる**。罫線・枠・影を最小に。グループ分けは余白と文字サイズで
3. **文字が主役**。提供価値シートは言葉のプロダクトなので、タイポグラフィに投資する。本文・見出しとも Noto Sans JP（ゴシック）で統一。見出しは太字で少し詰めて大きく。明朝は使わない（2026-10-07 決定）
4. **色は意味にだけ使う**。根拠タグ（緑・青・黄）、グレー（保留・落とした行）、アクセント1色（CTA・現在地）。それ以外はモノトーン
5. **動きは状態の変化を伝えるためだけ**。承認した行が静かに確定色に変わる、カウンタが増える、程度。装飾のアニメーションなし
6. **白紙を見せない**。どの画面も初期表示に下書きか問いがある。空の表を見せない
7. **AIは脇役**。チャット窓を中央に置かない。各セルの横に「下書き」「問い」として現れ、承認すれば消える
8. **顧客が見る数字は少なく**。行数カウンタ、残り生成件数、次のセッション日、未回答宿題数。それ以上は管理画面側

## 具体

- レイアウト: 左に細い進捗レール（アイコンなし、段階名のみ）、右に作業エリア。最大幅 1200px、中央寄せ
- 表（シート）: ヘッダ固定、行は高さ可変、セル内は折り返し。横スクロールより列の折りたたみ（列グループを開閉）
- 承認操作: 行の右端に「直す／承認／保留」を小さなテキストボタンで。承認済みは左に細い確定バー（アクセント色）
- 根拠タグ: 塗りつぶしではなく、セル左の細い縦線の色で示す（緑・青・黄）
- ダーク／ライト両対応。既定はライト
- モバイル: 閲覧と承認のみ対応（発散・生成はデスクトップ推奨の表示）
- 空状態の文言: 「あと x 行で統合に進めます」のように次の一手を書く。「データがありません」は使わない

## 技術

- Next.js (App Router) + TypeScript + Tailwind CSS。コンポーネントは shadcn/ui をベースに、上記原則に沿ってスタイルを削る
- アイコンは lucide を最小限
- フォント: `next/font` で Noto Sans JP（本文）＋ Inter（数字・英字）
