# 画面1：顧客画面

使う人: `customer_admin` / `customer_member`。状態（`companies.status`）で表示できるセクションが変わる。

## 共通レイアウト

- 左: 進捗レール（Step0 → 発散 → 統合 → 第2塗り④ → ⑤⑥ → ⑦ → 評価 → ⑩ → 展開）。現在地と、各段階の「行の厚み」（骨格／肉付け／仕上げ）を行ごとに薄い帯で示す
- 右: 作業エリア。AIとの対話はパネルではなく、各セルの横に出る「下書き」と「問い」で行う（チャット窓を主役にしない）
- 常時表示: 締切（次の確認セッション日）、未回答の宿題数、「ベレネッツに質問を残す」ボタン
- 顧客には絶対に出さないもの: operator の赤入れ（確認セッション前）、姿勢シグナル、評価軸の operator 点数（確認②前）、回天・脳科学手法名、システムプロンプト

## 1. Step0 会社資料のアップロード（状態: onboarding）

- ドロップゾーン（PDF・画像・URL）。種類を選ぶ（会社案内／製品パンフ／営業資料／Web／採用ページ／展示会／顧客の声／過去プレゼン）
- 明記する注意: 上げないもの（決算書・税務情報・顧客リスト・契約書・給与・人事情報）
- 自社理解サマリー: AIが draft を返す。項目ごとに「直す／承認／保留」。一括承認ボタンは置かない
- Q1「会社を一言で」: 適合診断時の回答を before として固定表示（編集不可）。after は確認③で入れる

## 1.5 Step0.5 競合の簡易リサーチ（状態: onboarding〜week1_2）

- 競合名を最大3社入力（＋参考1社）。STEP 0 の「競合他社」欄でお客様が登録：会社名（必須）・商品/サービス名・URL（`competitors.name/product/website/is_reference`、SQL 0027）。AIの下書き文脈（`loadProfileContext`）に「競合」として渡す
- AIが公開情報（HP・求人・レビュー・ニュース）から「顧客からの見え方／強み／弱み／訴求の言葉」を出所URL付きで下書き
- 顧客が直す／承認。承認後、第2塗りの競合比較列に流れる
- 出所が無い項目は生成しない（空欄＋「要確認」）

## 2. 発散週（状態: week1_2）

### 2.1 面の問い
- 1日1面。AIが今日の面と問い（周回別テンプレ）を出す。面＝機能的／情緒的／ターゲット別／起点タグ別（願望・恐れ・イライラ）／競合の弱みの裏返し／顧客の声／創業の経緯
- 周回: 1周目=広く／2周目=細分化（マイクロニッチ：「○○な人の中でも△△な人」）／3周目=面の掛け合わせ。2周目以降は前周の行を並べて「この面でまだ出ていないものは？」と問う
- 回答は行として即追加（value_raw）。AIが Step0 資料から下書き行も出す（created_by=ai、顧客が直す／承認／保留）

### 2.2 行数カウンタ
- 画面右上に常時: 現在 n 行／目標30／次へ進める20。面ごとの分布バー。薄い面をAIが指す
- 20行未満: 「統合案」列はロック（グレー・説明文「あと x 行で統合に進めます」）
- 削除ボタンは無い。行の操作は「保留」「別軸へ」のみ。落とした行はグレーで残る

### 2.3 統合→最終案（状態: week1_2 後半）
- AIが類似グループを提案（similar_group_id）。顧客はグループ単位で「統合する／しない」
- 統合案（value_merged）→ 最終案（value_final）。最終案の書き方ルールを横に固定表示: 主語は自社、「〜できる」、形容詞だけの価値は不可
- 各行に「一言で（中学生に説明する版）」欄

### 2.2.5 ふわっと診断（レビュー）の選択肢
- 各組の選択肢: この案で決定する（AI案あり時）／初期案（自社入力）のままにする／この組だけAIで別案を出す／一部自社で直す／保留にする／**却下する**
- 却下＝使わないと決めた組。`sheet_rows.status='dropped'`（物理削除しない）。組数（pair_count）から外れる。「却下した組」ブロックに取り消し線で並び、「戻す」で active に戻る。STEP 1 の一覧では「却下」のラベル

### 2.3.5 STEP 2 の出口（確認セッション①の案内）
- まとめて絞る の画面末尾に「次は、ベレネッツとの面談 ── 確認セッション①」ブロックを表示。出す条件＝レビューを1回以上行い、未対応の組が0（それまでは非表示。「次へ」も通常表示）
- `company_meetings` kind=session1 の未実施の予定が1件なら確定日時（と会議URL）を表示。**2件以上なら候補日として並べ、お客様が1つ選ぶ**（キックオフと同じ「選ぶ→◯◯でよろしいですか？→はい」。選ぶと他の候補は削除、`alerts` type=meeting_chosen を発行しベレネッツへメール）。0件なら「ベレネッツから日程のご連絡をしますので、お待ちください」
- 候補日の下に「すべての日程が難しい（別日を希望する）」→ 確認 → はい。候補はすべて取り下げ（キックオフは candidate_dates も空に）、`alerts` type=dates_declined を発行しベレネッツへメール。**お客様に希望日は入れさせない**（候補の提示はベレネッツ側からのみ）。ベレネッツが同じ種類の面談（キックオフは結果ページの候補日）を登録すると済み。キックオフ・確認セッション①②③・中間チェック共通
- 左の「次の面談」カードと左メニューの面談行も同じ判定：同じ種類の未実施が2件以上なら確定日を出さず「候補日が N 件届いています／ご都合のよい日を1つ選んでください →」（選ぶ画面へのリンク）
- 最下部の「次へ」は、面談が挟まる段階（gate.byOperator）では STEP 3 ではなく面談を「次」として出す。実施済みなら通常の表示に戻る（共通: `loadMeetingAfter` / `MeetingNextBlock`。確認セッション②も同じ仕組みで出す）

### 2.4 ニッチの試験紙（2問）
- 各最終案に ①見込み客は苦痛と緊急性、あるいは理性を超えた情熱を感じているか ②意欲を持って率先して解決策を探しているか → はい／いいえ／わからない
- AIの仮判定を薄く表示、顧客が確定。両方「いいえ」の行は保留候補（グレー）

### 2.5 第1塗りの固定文（セクション冒頭に常時表示）
「提供価値」はどちらかと言えば特徴。主語は御社で「〜できる」と書く。「体験価値」はどちらかと言えばメリット。主語はお客様で「〜と感じることができる」と書く。つなぎは「だから」。特徴→だから→メリット、と読んで自然なら合っている。

## 3. 第2塗り（状態: week3_5）

### 3.1 主ターゲット選択（独立画面）
- 確認①で封をしたターゲット候補（最大3）から主ターゲットを1つ選ぶ。行一覧とは別画面（行番号と混同させない）

### 3.2 ④4つの不（STEP 3 お客様のブレーキ ／ `/sheet/brakes`。実装済み）
- 開く条件: week3_5 以上（確認セッション①を実施済みにすると自動で進む）＋ STEP 0 に資料か説明がある
- 材料: STEP 2 で残した組（`sheet_rows.status=active`。却下・保留は出ない）
- 組ごとに 不信／不要／不適／不急 の4枠。各枠に複数枚可。1枚＝お客様の心の声（買い手の一人称）＋出所（お客様の声／面談記録／公式サイト／公開の声／自社の実感／AIの推測）＋根拠タグ（事実・要確認・仮説）
- 「AIの下書きを付ける」: ブレーキが無い組を最大6組ずつ（返答が途中で切れない量）。AIの返答が読めない・1枚も返らないときはエラーとして画面に出す。材料は `loadProfileContext`（STEP 0・適合診断・面談記録・資料・競合）。prompt key `brakes_draft`（DB）。source=ai は必ず hypothesis
- 顧客の操作: 直す（words/出所/タグ。created_by=customer, approved_at）／承認（approved_at）／外す（status=dropped、「外したブレーキ」から戻せる）／＋自分で書く（枠ごと）
- 仮説タグは承認しても黄のまま。出所が公開の声なら転載不可の注意
- 見出し数字＝そろった種類数/4。4種類そろうと STEP 4 へ（`brakeKinds>=4`）
- 固定文: `round2_brakes_intro`。4つの不の定義・例は `src/lib/brakes.ts`（一般語の説明のみ。メソッド本文はDB）
- 冒頭固定文（アクセル＝6大欲求／ブレーキ＝4つの不の定義と例。設計書の文面をそのまま）
- 行ごとに 不信／不要／不適／不急 のカード。AIが下書き（顧客の声・議事録・公式サイトから）。出所タグ必須。根拠が無いものは「仮説」タグ（黄）で出す
- 顧客は「直す／承認／保留」。仮説タグの行を承認しても黄のまま（事実化されるまで）
- 顧客アンケートが無い場合: 公開の声（レビュー・動画コメント）を材料にできる。原文はシート内のみ、販促物への転載不可の注意を表示

### 3.3 ⑤ひっくり返すメッセージ／⑥なぜなら
- 冒頭固定文（⑤は先回りの回答、⑥は根拠。事実／要確認／仮説の3段階）
- ⑤はAI下書き。数字・固有名詞の穴は空欄のまま出す（「○店で○台」）。穴が埋まるまで文は完成扱いにしない
- ⑥の根拠タグを色で表示（緑・青・黄）。行ごとの「事実0件」を目立たせる

### 3.4 ⑦体験価値をTRUSTで磨く
- 冒頭固定文（5つの角度）
- 行ごとにAIが角度違いの候補3つ。顧客が1つ選ぶ（書き換え可）。選ばれなかった候補も残す

### 3.5 競合比較
- 行×競合3社で 優位／同等／劣後／不明 と根拠。Step0.5の承認データを引く。要確認欄

### 3.6 社内打ち合わせの登録
- W3〜5で最低1回。日時を登録（未登録は黄色の注意）。前日にアジェンダ（未完了宿題・保留行・仮説タグの行）を自動メール

### 3.7 市場フィット試験紙（状態: week3_5 末）
- 6軸（業界の常識・非常識／投資価値／強み・資産／実現可能性／競合に勝てそうか／社内の熱意）＋ブランド構築の目的と合致＋マグニチュード（金額か件数で記入）＋増減除付メモ
- 顧客は自己採点を入れられる。operator の点数は確認②で開示。回天手法の軸は operator のみ

## 4. 第3塗り（状態: week6_8 / extended）

### 4.1 ⑩エビデンス
- 行ごとに「何を裏づけるか／内容／種別（実名の声／公開の声／第三者の数字／自社の事実）／出所／強さ」
- 冒頭固定文（証拠の強さの順、転記ルール）

### 4.2 展開（画面3へのリンク）
- 確認②で1位が封されていないと入れない

## 5. 宿題（全状態）

- 一覧: 優先（★）、確認事項、効く場所、期限、状態
- 各宿題の冒頭に固定文: 「一人で決めないでください。○○（役職ヒント）に聞いてから書いてください」
- 「誰に聞いたか」必須入力。「パス」ボタンはあるが、理由入力必須
- 担当者別メモ（member_notes）: customer_member も書ける

## 6. 猶予・ロック（状態: grace / locked）

- grace: 展開画面の残り生成件数（3件）と期限を表示。件数が尽きた時と期限1週間前に顧問の案内
- locked: シート閲覧、Excel一括ダウンロードのみ。展開画面はロック表示（「生成は顧問プランの範囲です。自社で作る手順は活用パッケージへ」）
- extended: 延長の残り週数を表示

## 7. Excelダウンロード（第1層の成果物）

全列統合版（順位／行No／①〜⑩／競合優位性／評価合計／封の状態）＋明細シート（⑤⑥、⑦候補、⑩、評価、競合、削除・保留行、宿題、凡例）。回天・脳科学手法名は含めない。

## 8. 追加リクエストへの返し（全状態・AI対話）

| 段階 | 返し |
| --- | --- |
| シートの中で答えられる（販促案・営業トーク等） | 展開画面へ誘導。grace/locked は制限表示 |
| シートの外だがブランディング範囲（新ターゲット・新商品） | 「シートにその行がありません。行を追加するには発散→4つの不→根拠の順で通す必要があります。ベレネッツに相談を残しますか」 |
| 経営・売上の相談 | 論点整理3〜5行＋関係する行を示し「この判断はベレネッツが人として返します」。`questions_to_operator.kind=escalation` |
| メソッド・出典の開示要求 | 固定の返し（05-ai-behavior.md）。`disclosure_requests` に記録 |

- 契約前（diagnosed）の左メニュー：「8週間で完成するもの」の枠＋ステップ一覧の間に面談（キックオフ／確認①／中間チェック／確認②／確認③）を差し込む（`ProgramOutline`。プレビューと共通）

- キックオフ候補日：結果ページの候補日（diagnosis_results.candidate_dates）と、面談に登録した未実施のキックオフ（company_meetings）の両方を候補として出す（未来の日だけ）。結果ページに候補が無く面談に1件だけなら確定扱い。お客様が選ぶと、選んだ日の面談を残し、ほかの未実施候補は外す（`src/server/kickoff.ts`）。

- 申込後（diagnosed かつ applied_at/contracted_at/paid_at のいずれか有り）：ホーム `/` が「キックオフまでの進み具合」（申込→契約→入金→キックオフ日、`ProgramStart`）になり、診断結果は「振り返り」リンク。診断結果ページは判定の帯を「振り返り用」に変え、2つの道・多くの会社がやること・申込の導線を出さない。左メニューのフェーズ表示も「お申し込み済み（契約手続き中）」「キックオフ前（日程調整）」に。

- STEP 0 が空（資料・URLが0件かつ承認・修正済みの説明が0項目）のうちは、STEP 1 以降を開かない。左メニューは準備中扱い、ホームの「いま進めること」は STEP 0、直接開くと STEP 0 への案内（`Step0Required`）。判定は `isStep0Ready()`。
