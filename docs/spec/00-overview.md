# 選ばれる理由AI — 概要と状態遷移

最終更新: 2026-10-07 ／ 出典: 「選ばれる理由AI」サービス設計書 v1（Claude Doc）

## 1. 何を作るか

中小企業が8週間で「提供価値シート」（自社が選ばれる理由の脚本）を完成させ、それを営業・価格説明・Web・採用などの接点に展開するためのブラウザアプリ。ベレネッツ（運営）が伴走し、AIが下書き・問い・生成を担う。

商品構造は「提供価値の言語化 → AIに搭載 → 接点に展開」の順番そのもの。

| 層 | 内容 | 顧客に残るもの |
| --- | --- | --- |
| 第1層 | 完成した提供価値シート（全列） | Excel生データ（全列・出所タグ・根拠タグ・削った行と理由・競合比較・顧客の声の分類表・未回収宿題） |
| 第2層 | 貴社専用の選ばれる理由AI | アプリ（顧問期間中は継続利用） |
| 第3層 | 活用パッケージ | 接点マップ／営業トーク台本／価格説明／Web原稿／採用EVP／見積の言葉／社内共有用1枚／月次運用の型 |

## 2. 登場人物（ロール）

| ロール | 説明 |
| --- | --- |
| `customer_admin` | 顧客企業の担当者（決裁者または実務担当）。画面1・3を使う |
| `customer_member` | 顧客企業の他メンバー（担当者別メモ列に書ける。承認はできない） |
| `operator` | ベレネッツ。画面2を使う。赤入れ・封・評価軸・順位は operator のみ |
| `system` | AI・スケジューラ |

## 3. 顧客企業の状態遷移

```
 diagnosed ──契約──▶ onboarding ──Day0完了──▶ week1_2 ──確認①──▶ week3_5 ──確認②──▶ week6_8 ──確認③──▶ grace ──1か月──▶ locked
                                                                                          │                       │
                                                                                          └──延長(最大4週)──▶ extended ──確認③──▶ grace
                                                                                                                  │
                                                                                                   延長超過 ──▶ advisor（顧問扱い）
 grace ──顧問契約──▶ advisor ──解約(1か月前通知)──▶ cancelled
 advisor ──再開(シート更新セッション)──▶ advisor
```

| 状態 | 意味 | 使える機能 |
| --- | --- | --- |
| `diagnosed` | 適合診断済み・未契約 | なし（operator が診断メモを登録） |
| `onboarding` | 契約済み・Day0前 | Step0 資料アップロード、自社理解サマリー修正、Step0.5 競合リサーチ |
| `week1_2` | 第1塗り（発散週） | 発散（7面）、統合、ニッチ試験紙2問、宿題 |
| `week3_5` | 第2塗り | ④⑤⑥⑦、競合比較、宿題、社内打ち合わせ登録 |
| `week6_8` | 第3塗り | ⑩エビデンス、展開画面（活用パッケージ生成） |
| `extended` | 確認③を最大4週間延長 | week6_8 と同じ。残り週数を表示 |
| `grace` | 確認③後1か月の猶予 | 展開画面（生成3件まで）、シート閲覧、Excel DL |
| `locked` | 猶予終了・顧問未契約 | シート閲覧、Excel DL のみ |
| `advisor` | 顧問契約中 | 展開画面（月10件）、判断会議、シート更新、計測レビュー |
| `cancelled` | 解約 | 解約前の一括ダウンロードのみ（期限付き） |

状態遷移は operator の操作（確認セッションの「封をする」ボタン、契約状態の変更）か、スケジューラ（猶予期限・延長期限）で起きる。顧客自身は状態を進められない。

## 4. 8週間の流れ（顧客／AI／operator）

| 週 | 顧客 | AI | operator |
| --- | --- | --- | --- |
| Day0 | キックオフ＋WS（3時間） | — | 講義・使い方 |
| W1 | 発散：毎日1面の問いに答えて提供価値を出す（目標30行、20行以上で次へ）。Step0.5競合リサーチを直す | 面ごとの問い・下書き・類似統合の提案 | 停滞アラート |
| W2 | 統合案→最終案。ニッチ試験紙2問で粗ふるい。顧客3社に聞く | 統合案の提案、試験紙の仮判定 | 確認①（60分）：①〜③に封 |
| W3〜4 | ④4つの不→⑤⑥→⑦TRUST。社内打ち合わせ最低1回（登録必須） | 下書き・根拠タグ | 停滞アラート・打ち合わせ前日アジェンダ・W3末 中間チェック（15〜20分、詰まりを聞くだけ） |
| W5 | 市場フィット試験紙＋マグニチュード＋増減除付 | 仮採点 | 確認②（90分）：⑧⑨・順位・封 |
| W6〜7 | ⑩エビデンス。活用パッケージ生成 | 展開生成・対応表 | 停滞アラート |
| W8 | 活用パッケージの赤入れ・社内共有用1枚 | — | 確認③（60分）：全列に封・運用設計・顧問案内 |

## 5. 封（lock）のルール

- 封＝確認セッションで確定した列は以降の塗りで原則変えない。変える場合は理由を記録（`sheet_lock_history`）。
- 確認①：①ターゲット ②提供価値（最終案）③6大欲求
- 確認②：④〜⑦・⑧⑨・順位・競合優位性・評価軸の点数
- 確認③：全列（⑩エビデンス含む）
- 仮封：封の形だが、根拠タグが「仮説」「要確認」のままの列。宿題回収後に差し替え可
- 封をブロックする条件（operator に警告。強制はしない）：⑤⑥の根拠が「事実」1件もない行を1位にしようとしている

## 6. 価格・回数（内部情報。顧客画面には出さない）

- 初期8週間：70万円（検討中）。前払い。確認①までは半額返金、以降返金なし
- 顧問：月額（未定）。最低3か月、1か月前通知で解約、月末締め日割りなし
- 面談5回：キックオフ＋WS／確認①／中間チェック／確認②／確認③。別に契約前の適合診断45分
- 展開生成上限：猶予中3件、顧問月10件
- 受入の内部目標15社（開始時期をずらす）

## 7. 用語

| 用語 | 意味 |
| --- | --- |
| 提供価値 | 自社の特徴。主語は自社、「〜できる」 |
| 体験価値 | 顧客のメリット。主語は顧客、「〜と感じることができる」 |
| 塗り | 第1塗り（骨格）→第2塗り（肉付け）→第3塗り（仕上げ） |
| 根拠タグ | 事実／要確認／仮説 |
| 出所タグ | 議事録／公式サイト／顧客の声（YouTube等）／仮説／AI提案 |
| 面 | 発散週で提供価値を探す7つの切り口 |
| 展開 | 1位の提供価値を接点の言葉に変換すること |
