# 画面2：ベレネッツ管理画面

使う人: `operator` のみ。

## 1. 全社一覧

- 列: 会社名／状態／現在地（塗り・列）／次のセッション日／停滞日数／未回収宿題数／姿勢シグナル該当数／本業引き上げフラグ／開示要求回数
- 停滞7日以上は黄色。ワンクリックで「ひと押しメール」（テンプレ）
- フィルタ: 状態、今週セッションがある会社、フラグあり

## 2. 1社の詳細

### 2.1 進捗の位置
現在地と次のマイルストーン。塗りごとの承認状況（確定／保留／未レビューの行数）。顧客の作業ログ（いつ・どの行を・直した／承認／保留）。

### 2.2 停滞シグナル（外圧の材料）
- 宿題の回答状況と影響の自動算出（例: 「★★★3件が未回収 → ⑤⑥の要確認15件中9件が事実にならない」）
- 最終ログインからの経過日数、未レビュー行数
- 社内打ち合わせ未登録（W3〜5）

### 2.3 悩みの材料（セッションで話すこと）
- 保留が溜まった項目
- AI下書きと顧客の修正文の差分（並べて表示。最大の材料）
- 「ベレネッツに質問を残す」の未回答
- 根拠タグの分布（事実／要確認／仮説）＝適合診断3軸（素材・言語化・姿勢）の継続計測

### 2.4 姿勢シグナル
ログから機械的に拾う。単体では断定せず、複数該当でフラグ。点数ではなく事実の組み合わせで表示し、根拠の行番号にリンク。

| 系統 | サイン |
| --- | --- |
| 承認の仕方 | 10行以上を「直す」「保留」なしで連続承認／1行の滞在時間が文字数を読む時間を下回る／仮説タグの行を修正も保留もせず承認／行同士が矛盾したまま承認 |
| 修正の中身 | 全塗り通して修正文字数0／句読点・語尾だけの修正／「御社にしか書けない空欄」が埋まらないまま次へ／Q1が一度も触られていない |
| 時間の使い方 | セッション前日・当日に作業集中／1回のログインで全行処理／最終ログインからの空白日数 |
| 宿題 | 回答率、パス数／回答が「分からない」「ない」だけで誰に聞けば分かるかが無い |

表示例: 「3つが重なっています：仮説12件を全承認／修正ゼロ／宿題0件」→ セッションで聞く問いに変換して出す（「④の仮説、全部あるあるでしたか？」）。

### 2.5 赤入れ
- ⑤⑥⑦・⑧⑨の operator 版を入力。確認セッションまで顧客に非公開（セッション時に「開示」ボタン）
- 評価軸: 市場フィット6軸＋ブランド目的合致＋マグニチュード＋回天手法（1〜5ステップ）＋増減除付→順位。AIの仮採点を横に表示
- 競合優位性（どこ・どのように）
- 「封をする」ボタン（確認①／②／③）。封をブロックする条件の警告（⑤⑥に事実0件の行を1位にしようとしている等）。仮封のチェック
- 延長（最大4週）の付与、猶予・顧問の状態変更

### 2.6 開示要求ログ・本業引き上げ
- `disclosure_requests` の一覧（日時・質問文）。同一社3回以上で alert
- `questions_to_operator.kind=escalation` の一覧（売上・経営相談）。本業引き上げ候補フラグ

### 2.7 展開物のレビュー
- `deployments.status=awaiting_review` の一覧。生成物とブロック別の対応表（使った行・根拠タグ・**使った回天／脳科学手法**）。承認／差し戻し（理由）
- 顧問の月の生成数（10件）と猶予の残り（3件）

## 3. メソッド資産の管理（operator の中でも管理者のみ）

- 7面の問いテンプレ（周回別）、各塗りの固定文、回天×脳科学の手法表、システムプロンプト（バージョン管理）
- ここで投入した本文はサーバ側のみで使い、顧客向けAPIには出ない
